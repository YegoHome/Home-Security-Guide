Your Home Security Guide

Part 3: The Guest Rooms

Your front doors are locked. But if you run virtual machines, you also have guest rooms inside your home, and each one has its own doors.

About 20 minutes per guest roomAdministrator permission needed

No virtual machines? You can skip ahead to Part 4.

How Guest Rooms Work

The house metaphor
  • A guest room (virtual machine) is a separate computer running inside yours. It has its own doors and its own locks.
  • The locks from Part 2 protect your doors. They don't lock the guest room's doors. Each guest room needs its own walk and its own locks.
  • A hallway (port forwarding rule) leads visitors from one of your outside doors straight to a guest room door. Every hallway stays open until you remove it.
  • The sealed wing is a virtual network only your guest rooms share. It's the safest place for testing (Part 5).

What we'll do

  1. Find out which guest-room program you use.
  2. Check how each guest room connects to the outside.
  3. Walk and lock each guest room from the inside.
  4. Find every hallway, log it, and remove the ones you no longer need.

Step 1: Which Program Builds Your Guest Rooms?

Press the Windows key and type the names below. Whatever appears tells you what you have.

Search forProgramWorks on
Hyper-V ManagerMicrosoft Hyper-V (built into Windows)Windows 11 Pro and Enterprise only. It can't be installed on Windows 11 Home.
VirtualBoxOracle VirtualBox (separate download)Windows 11 Home and Pro

This guide covers Hyper-V and VirtualBox. If you use something else, its own documentation will show where its network and port forwarding settings are. The ideas on these pages still apply.

Write down the name of every guest room (virtual machine) you see in Hyper-V Manager or VirtualBox. You'll need these names soon.

Step 2: How Does Each Guest Room Connect?

Each guest room's network setting decides who can reach its doors.

SettingIn the houseWho can reach the guest room
Hyper-V External switch · VirtualBox BridgedThe guest room has its own door to the streetOther devices on your network, like any other computer
Hyper-V Internal switch · VirtualBox Host-onlyThe door opens only into your homeYour computer and other guest rooms on the same setting
Hyper-V Private switch · VirtualBox Internal NetworkThe sealed wingOnly other guest rooms on the same network, not even your computer
VirtualBox NAT (the default)The guest shares your front doorNobody from outside, unless you add a hallway

Check Hyper-V (Terminal (Admin))

Get-VMSwitch | Format-Table Name, SwitchType -AutoSize
Get-VMNetworkAdapter -VMName * | Format-Table VMName, SwitchName, IPAddresses -AutoSize

Check VirtualBox

Select a guest room → Settings → Network. Each enabled adapter shows Attached to (NAT, Bridged Adapter, Internal Network, Host-only Adapter, and so on).

Sources: Microsoft Learn, Hyper-V virtual switches; Oracle VirtualBox networking modes.

Step 3: Walk and Lock Each Guest Room

Start the guest room and sign in inside it. Everything on this page happens inside the guest, not on your own computer.

Windows guest rooms

  1. Repeat the Part 1 Security Walk inside the guest.
  2. Repeat the Part 2 locks inside the guest, using the same Lock - names.
  3. Close the gate (exit) inside the guest when done.

Linux guest rooms (Ubuntu example)

List open doors and mail slots with the program behind each:

sudo ss -tulpn

Check the guest room's own locks (Ubuntu's built-in firewall, ufw):

sudo ufw status verbose
If ufw says inactive, the guest room has no locks of its own. Ubuntu's ufw documentation explains how to turn it on. Before you do, allow any door you still need, such as SSH if you connect that way.
Same rule in every room: a door bound to 127.0.0.1 is an inside door. A door on 0.0.0.0 or [::] (shown as * in ss) faces every side of the guest room.

Step 4: Find Every Hallway

Hyper-V hallways (Terminal (Admin))

Get-NetNat
Get-NetNatStaticMapping |
  Format-Table StaticMappingID, NatName, Protocol, ExternalPort, InternalIPAddress, InternalPort -AutoSize

Each line from Get-NetNatStaticMapping is one hallway: visitors who arrive at ExternalPort are walked to InternalIPAddress : InternalPort in a guest room. Source: Microsoft Learn, Get-NetNatStaticMapping.

No output? You have no Hyper-V hallways of this kind. That's a good result.

VirtualBox hallways

By clicking: select the guest room → Settings → Network → an adapter set to NAT → expand Advanced → Port Forwarding.

By command (standard Terminal on your computer; replace VM name):

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" showvminfo "VM name" | findstr Rule

Each Rule line is one hallway, showing its name, host port (outside door), and guest port (guest room door).

Step 5: Log Every Hallway

For each hallway you found, decide: Keep (you use it now) or Remove (you don't). Record it here so nothing is forgotten.

Guest roomProgramOutside doorGuest doorDecisionActions

This log isn't saved when you leave the page. Copy it into your Security_Walk_Notes.txt file from Part 1.

Step 6: Remove Stale Hallways

Hyper-V (Terminal (Admin))

Use the StaticMappingID number from Step 4. This example removes hallway number 3:

Remove-NetNatStaticMapping -StaticMappingID 3
Always include the ID. Microsoft's documentation shows that Remove-NetNatStaticMapping with no ID removes every static mapping on the computer.

VirtualBox

By clicking: open the Port Forwarding window from Step 4, select the rule, click the remove (minus) button, then OK.

By command, replacing VM name and rule name. If the guest room is switched off:

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" modifyvm "VM name" --natpf1 delete "rule name"

If the guest room is running:

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" controlvm "VM name" natpf1 delete "rule name"

natpf1 means adapter 1. Use natpf2 for adapter 2, and so on. Source: Oracle VBoxManage reference.

Step 7: Check the Hallways Are Gone

  1. Run the Step 4 commands again. The hallways you removed should no longer be listed.
  2. On your own computer, check whether anything is still listening on the old outside door (replace 2222 with your port):
Get-NetTCPConnection -State Listen -LocalPort 2222 -ErrorAction SilentlyContinue

No output means that outside door is closed.

Remove leftover locks or openings for removed hallways

If you ever added a firewall rule on your computer to let visitors into a hallway, remove that too. In wf.msc → Inbound Rules, find the rule by its name, right-click → Delete.

Close the gate in every window you opened, on your computer and inside each guest room.
