Part 5: The Regular Patrol

Homes change. New apps open doors, tests leave doors ajar, and old hallways get forgotten. A regular patrol catches these changes early.

About 25 minutes to set up5 minutes each month after that

How the Patrol Works

The house metaphor
  • The patrol is a regular walk through your home with a flashlight. It only looks and changes nothing.
  • The logbook is a dated text file the patrol writes, so you can compare this month with last month.
  • A temporary test door is a short-lived opening for testing. It's always named "TEMP - ", used only in the sealed wing or on your home network, and removed the same day.

What we'll set up

  1. A read-only patrol script that writes a logbook
  2. A schedule that runs it every four weeks
  3. A way to compare two logbooks
  4. A safe routine for temporary test doors
  5. A monthly checklist

Step 1: Create the Patrol Script

Open a standard Terminal and create a folder for the patrol:

New-Item -ItemType Directory -Path "$env:USERPROFILE\SecurityPatrol" -Force
notepad "$env:USERPROFILE\SecurityPatrol\Patrol.ps1"

If Notepad asks whether to create a new file, select Yes. Copy the script on the next page into Notepad, then save it with Ctrl + S.

Why this folder? $env:USERPROFILE is your own user folder (for example, C:\Users\YourName). It isn't moved by OneDrive the way Documents or Desktop sometimes are, so the schedule always finds the script.
The script is read-only. Every command in it starts with Get-, which only reads information. The only thing it writes is the logbook file.

The Patrol Script

# Patrol.ps1 - Home Security Guide, Part 5
# Read-only: this script only looks and writes a logbook. It changes nothing.

$folder = $PSScriptRoot
$stamp  = Get-Date -Format 'yyyy-MM-dd_HHmm'
$log    = Join-Path $folder "Patrol_$stamp.txt"

function Add-Section {
    param([string]$Title, $Data)
    "`r`n=== $Title ===" | Out-File -FilePath $log -Append -Encoding utf8
    if ($Data) { $Data | Out-String -Width 250 | Out-File -FilePath $log -Append -Encoding utf8 }
    else       { '(none found)' | Out-File -FilePath $log -Append -Encoding utf8 }
}

$program = @{ Name = 'Program'; Expression = { (Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue).ProcessName } }

"Patrol run: $(Get-Date)   Computer: $env:COMPUTERNAME" | Out-File -FilePath $log -Encoding utf8

Add-Section 'Open doors (TCP LISTENING) - Part 1' (Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Sort-Object LocalPort, LocalAddress | Select-Object LocalAddress, LocalPort, $program | Format-Table -AutoSize)

Add-Section 'House type (network profile) - Part 2' (Get-NetConnectionProfile -ErrorAction SilentlyContinue |
    Select-Object Name, InterfaceAlias, NetworkCategory | Format-Table -AutoSize)

Add-Section 'My locks (Lock - rules) - Part 2' (Get-NetFirewallRule -DisplayName 'Lock - *' -ErrorAction SilentlyContinue |
    Sort-Object DisplayName | Select-Object DisplayName, Enabled, Action, Profile | Format-Table -AutoSize)

Add-Section 'Temporary test doors (TEMP - rules) - should be none' (Get-NetFirewallRule -DisplayName 'TEMP - *' -ErrorAction SilentlyContinue |
    Select-Object DisplayName, Enabled, Action, Profile | Format-Table -AutoSize)

Add-Section 'Hyper-V hallways (NAT static mappings) - Part 3' (Get-NetNatStaticMapping -ErrorAction SilentlyContinue |
    Select-Object StaticMappingID, NatName, Protocol, ExternalPort, InternalIPAddress, InternalPort | Format-Table -AutoSize)

Add-Section 'Remote Desktop envelope - Part 4' (Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp' -ErrorAction SilentlyContinue |
    Select-Object SecurityLayer, UserAuthentication | Format-List)

Add-Section 'File sharing - Part 4' (Get-SmbServerConfiguration -ErrorAction SilentlyContinue |
    Select-Object EnableSMB1Protocol, EncryptData | Format-List)

The logbook leaves out process ID numbers on purpose. Those numbers change every time Windows restarts, so leaving them out keeps month-to-month comparisons clean.

Step 2: Do a Test Patrol

Some readings, such as your firewall rules, may need the master keys. The scheduled patrol runs with them, so test it the same way: open Terminal (Admin) and run:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\SecurityPatrol\Patrol.ps1"
explorer "$env:USERPROFILE\SecurityPatrol"

A File Explorer window opens with a new file named like Patrol_2026-11-09_1430.txt. Open it and check each section has content, or says (none found).

About -ExecutionPolicy Bypass: Windows blocks scripts by default. This option allows this one run only. It doesn't change your computer's settings.
If you seeDo this
"cannot be loaded because running scripts is disabled"Make sure you included -ExecutionPolicy Bypass exactly as shown.
"cannot find the path"Check the file is saved as Patrol.ps1, not Patrol.ps1.txt. In Notepad's Save dialog, set Save as type to All files.

Step 3: Schedule the Patrol

In the same Terminal (Admin) window, run this to patrol every four weeks on Sunday at 9:00 AM:

$script   = "$env:USERPROFILE\SecurityPatrol\Patrol.ps1"
$action   = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument "-NoProfile -ExecutionPolicy Bypass -File `"$script`""
$trigger  = New-ScheduledTaskTrigger -Weekly -WeeksInterval 4 -DaysOfWeek Sunday -At 9am
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable
Register-ScheduledTask -TaskName 'Home Security Patrol' -Action $action -Trigger $trigger -Settings $settings -RunLevel Highest
  • Every four weeks: Microsoft documents -WeeksInterval as the gap between weeks in the schedule. This command doesn't offer a "monthly" option, so 4 is the closest.
  • StartWhenAvailable runs a missed patrol as soon as possible, for example if the PC was off on Sunday morning.
  • The patrol runs while you're signed in. A window may flash briefly.

Manage the schedule

Get-ScheduledTask -TaskName 'Home Security Patrol'            # check it exists
Start-ScheduledTask -TaskName 'Home Security Patrol'          # run it now
Unregister-ScheduledTask -TaskName 'Home Security Patrol' -Confirm:$false   # remove it

Step 4: Compare Two Logbooks

Once you have two logbooks, this shows only what changed:

$logs = Get-ChildItem "$env:USERPROFILE\SecurityPatrol\Patrol_*.txt" | Sort-Object LastWriteTime | Select-Object -Last 2
Compare-Object (Get-Content $logs[0].FullName) (Get-Content $logs[1].FullName)
ArrowMeaning
=>Only in the newer logbook (something new appeared)
<=Only in the older logbook (something went away)

The "Patrol run" date line always differs. That's expected.

What to look for

  • A new open door: find who opened it (Part 1, Step 5).
  • A door that moved from an inside door (127.0.0.1) to a door on every side (0.0.0.0)
  • A lock showing Enabled False, or a lock missing (Part 2)
  • A house type that changed from Public to Private (Part 2, Step 1)
  • Any TEMP - rule still installed (Step 5 on the next page)
  • A new Hyper-V hallway you don't recognize (Part 3)

Step 5: Temporary Test Doors, Done Safely

Sometimes you need to open a door briefly, for example to test an app. Follow these four rules every time.

  1. Test in the sealed wing first. Run the test between guest rooms on a Hyper-V Private switch or VirtualBox Internal Network (Part 3). Nothing outside the wing can reach it.
  2. If you must test on this PC, give the test door a household key and limit it to the Private house type.
  3. Name it with TEMP, the door number, and today's date.
  4. Use a different door number each session, and remove the door the same day.

Check a door number is free

Get-NetTCPConnection -State Listen -LocalPort 8081 -ErrorAction SilentlyContinue

No output means door 8081 isn't in use.

Open the temporary test door (Terminal (Admin))

New-NetFirewallRule -DisplayName "TEMP - Test 8081 - 2026-11-09" -Direction Inbound -Protocol TCP -LocalPort 8081 -Action Allow -Profile Private -RemoteAddress LocalSubnet

Change the door number and date each time. -RemoteAddress LocalSubnet is the household key. It's one of the keywords Microsoft documents for this setting.

If your house type is Public (Part 2), this rule has no effect, because it only applies on Private networks. That's another reason the sealed wing is the better place to test.

Step 6: Remove Every Test Door

Firewall rules don't expire on their own. Remove test doors at the end of each session.

See which test doors exist

Get-NetFirewallRule -DisplayName "TEMP - *" | Format-Table DisplayName, Enabled, Profile -AutoSize

Remove all of them

Get-NetFirewallRule -DisplayName "TEMP - *" | Remove-NetFirewallRule

Confirm they're gone

Get-NetFirewallRule -DisplayName "TEMP - *" -ErrorAction SilentlyContinue

No output means every test door is removed. Your next patrol logbook will show (none found) in the temporary test doors section.

Also check the guest rooms. If you added test doors or hallways inside a guest room, remove them there too (Part 3, Step 6). Then close the gate with exit.

Step 7: Your Monthly Patrol Checklist

Tick each item as you go. The ticks reset when you leave the page, ready for next month.

Guest rooms get a patrol too. In each Windows guest room, repeat Steps 1–3 inside the guest so it keeps its own logbook.
