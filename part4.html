Part 4: Sealed Envelopes

Some doors stay open on purpose, such as Remote Desktop or file sharing. For those, the goal changes: make sure everything said through them is sealed.

About 20 minutesMostly read-only checks

This is an experimental learning guide. If you apply any step, you do so at your own risk. Please read the Disclaimer first.

Locks and Envelopes

The house metaphor
  • A lock (Parts 2 and 3) decides who can reach a door.
  • A postcard (unencrypted traffic) can be read by anyone it passes on the way.
  • A sealed envelope (TLS encryption) keeps the message private and shows if anyone tampered with it.
  • An ID badge (certificate) proves the computer answering really is the one you meant to reach.

You need both. A locked door with a household key still lets your home devices in, and what they say should be sealed.

What we'll check

  1. Which talking doors are open on this PC
  2. Remote Desktop (door 3389)
  3. File sharing (door 445)
  4. Envelope strength (TLS versions)
  5. Any server app you installed yourself

Step 1: Find the Talking Doors

Open a standard Terminal (the visitor pass) and check the doors that usually carry conversations:

Get-NetTCPConnection -State Listen -LocalPort 80,443,445,3389,5985,5986 -ErrorAction SilentlyContinue |
  Sort-Object LocalPort |
  Format-Table LocalAddress, LocalPort, OwningProcess -AutoSize
DoorUsuallyGo to
3389Remote DesktopStep 2
445File sharing (SMB)Step 3
80, 443A web server or app you installedStep 5
5985, 5986PowerShell remote management (WinRM)See below

No output means none of these doors are open. Read the pages anyway so you know what to check if one appears later.

About 5985 and 5986: Microsoft says Windows Server is enabled for PowerShell remoting by default, but other Windows computers, such as Windows 11 PCs, must have remoting turned on before they accept remote connections. If either door appears and you didn't set up remote management on purpose, write it down and ask whoever manages this PC. If this is a work PC, ask your IT department.

Step 2: The Remote Desktop Door (3389)

Windows 11 Home can't accept Remote Desktop visitors. Only Pro and Enterprise editions can. On Home, you can skip this page.

Check the setting

  1. Open Settings → System → Remote Desktop.
  2. Don't use it? Turn Remote Desktop to Off. That closes door 3389.
  3. Do use it? Make sure Require devices to use Network Level Authentication to connect is turned on. Microsoft recommends this option.
The house metaphorNetwork Level Authentication is an ID check at the gate. Visitors must prove who they are before the door even opens.

Confirm the envelope (read-only)

Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp' |
  Select-Object SecurityLayer, UserAuthentication
ValueMeaning
SecurityLayer 2TLS is used to set up the connection (sealed envelope)
SecurityLayer 1Negotiate: client and server agree on the method (the Windows default)
SecurityLayer 0Older RDP security, not TLS
UserAuthentication 1Network Level Authentication is required

Source: Microsoft Learn, SecurityLayer.

Remote Desktop: Give It a Household Key

If you keep Remote Desktop on, limit it to devices on your home network. This uses the same household key as Part 2.

  1. Open the security desk: Windows + R → wf.msc → Yes.
  2. Select Inbound Rules and find Remote Desktop - User Mode (TCP-In).
  3. Double-click it → Scope tab → under Remote IP address, choose These IP addresses → Add...
  4. Choose Predefined set of computers → Local subnet → OK → OK.
  5. Repeat for Remote Desktop - User Mode (UDP-In).
Remote Desktop over the internet: this guide doesn't cover opening Remote Desktop to the internet (for example, with port forwarding on your router). If you need access from outside your home, use a secure method your router or VPN provider documents, and don't create a router hallway straight to door 3389.

Step 3: The File-Sharing Door (445)

Your path from Part 2: not chosen yet

Everyone: check for the old postcard protocol

Get-SmbServerConfiguration | Format-List EnableSMB1Protocol, EncryptData
  • EnableSMB1Protocol : False is what you want. SMB1 is the old version of file sharing. Microsoft's guide explains how to detect and disable it.
  • EncryptData : False means Windows doesn't require every file-sharing conversation to be sealed.
Path A: your Part 2 locks already stop visitors at door 445 on every network. No further change is needed.

Path B: seal every file-sharing envelope (optional)

In Terminal (Admin):

Set-SmbServerConfiguration -EncryptData $true

Type Y if asked to confirm. Devices that only support older file-sharing versions won't be able to connect after this. To undo:

Set-SmbServerConfiguration -EncryptData $false
Choose your path in Part 2, Step 2 to see the matching instructions here.

Step 4: Envelope Strength (TLS Versions)

TLS 1.0 and 1.1 are old, weak envelopes. Microsoft says that starting with Windows 11 Insider Preview builds in September 2023, and continuing in future Windows releases, they are disabled by default.

Check what your PC has been told (read-only)

Get-ChildItem 'HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols' -Recurse -ErrorAction SilentlyContinue |
  ForEach-Object { [pscustomobject]@{ Protocol = $_.PSParentPath.Split('\')[-1]; Side = $_.PSChildName; Enabled = $_.GetValue('Enabled') } } |
  Where-Object { $_.Side -in 'Client','Server' } | Format-Table -AutoSize
You seeMeaning
Nothing, or no Enabled valueNo override. Windows uses its built-in defaults.
TLS 1.0 or TLS 1.1, Enabled 1Something turned the old envelopes back on
TLS 1.0 or TLS 1.1, Enabled 0Old envelopes are switched off
If TLS 1.0 or 1.1 shows Enabled 1: an app on this PC may have needed it. Write down the result and check with whoever set up the PC or the app's maker before changing it.

Optional: Turn Off the Old Envelopes

Only do this if Step 4 showed TLS 1.0 or 1.1 with Enabled 1 on the Server side, and you've confirmed nothing needs them. It affects visitors connecting to this PC.

In Terminal (Admin):

reg add "HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.0\Server" /v Enabled /t REG_DWORD /d 0 /f
reg add "HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.1\Server" /v Enabled /t REG_DWORD /d 0 /f

Microsoft's TLS registry settings page says setting Enabled to 0 disables a protocol version, and that apps or services may need a restart to pick it up. Restart your PC so every service picks it up.

To undo

Delete the values you added. Windows then goes back to its defaults:

reg delete "HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.0\Server" /v Enabled /f
reg delete "HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.1\Server" /v Enabled /f

Then restart again. Close the gate with exit.

Step 5: Server Apps You Installed

If Step 1 showed doors 80, 443, or any other door that belongs to a program you installed (a media server, game server, or web app):

  1. Open that app's settings or documentation and look for HTTPS, TLS, or SSL.
  2. Turn it on and give it a certificate (ID badge), following the app maker's instructions.
  3. Turn off the unencrypted option (often door 80) if the app allows it.
  4. Give the app's firewall rule a household key, as in Part 2, Step 7.

Check which envelope a door uses

This read-only check connects to a door and reports the TLS version. Try it first with a public site, then replace both names with your app's address:

$name = 'www.microsoft.com'
$tcp  = New-Object System.Net.Sockets.TcpClient($name, 443)
$ssl  = New-Object System.Net.Security.SslStream($tcp.GetStream())
$ssl.AuthenticateAsClient($name)
"Envelope: " + $ssl.SslProtocol
$ssl.Dispose(); $tcp.Dispose()

You should see Tls12 or Tls13. An error on the AuthenticateAsClient line usually means the ID badge isn't trusted by this PC (for example, a self-signed certificate) or the door doesn't use TLS.
