Part 2: Managing the Locks

Welcome back. In Part 1, you walked around your digital home and wrote down which doors were open.

Now you'll lock the risky ones.

About 20 minutesAdministrator permission neededHave your Part 1 notes ready

How Locks Work

The house metaphor
  • An open door = anyone who can reach it can walk up and try to come in.
  • A locked door = visitors from other devices are stopped. Nobody has a key.
  • A locked door with a household key = strangers are stopped, but devices on your own home network can still come in.

The program behind a locked door keeps running. The lock only stops visitors arriving from other devices.

What we'll do

  1. Check your house type (Public or Private network).
  2. Use the security desk (Windows Defender Firewall) to add locks. This part uses clicks, not commands.
  3. Check your locks with one read-only command at the end.
Everything here can be undone. Page 11 shows how to switch off or remove any lock in seconds.

Step 1: Check Your House Type

Windows treats each network you join as Public or Private. This decides which built-in doors Windows opens.

  1. Open Settings → Network & internet.
  2. Select Wi-Fi and then your network, or select Ethernet.
  3. Find Network profile type.
House typeWhat Microsoft says
Public network (Recommended)Your PC is hidden from other devices on the network, so it can't be used for file and printer sharing. Recommended for most networks, including home.
Private networkYour PC is discoverable and can be used for file and printer sharing. Only for networks where you know and trust the people and devices.

Source: Microsoft Support, essential network settings.

Simplest safe choice: if you don't share files or a printer from this PC, keep the network set to Public.

Step 2: Choose Your Path

Do other devices in your home open files or use a printer that's connected to this PC?

Pick a path above. The rest of Part 2 (and Part 4) will show the matching steps. You can change it any time.
Path A: locks go on all three profiles (Domain, Private, Public). Nobody gets a key. This PC can still open files and printers on other devices, because these locks only stop visitors coming in.
Path B: locks for doors 135, 139 and 445 go on Domain and Public only. That way, on public Wi-Fi nobody gets in, while at home Windows' own sharing rules handle visitors. In Step 7 you'll give those sharing rules a household key, so only devices on your home network get in.

Step 3: Open the Security Desk

This is where locks are installed and removed.

  1. Press Windows + R.
  2. Type wf.msc and press Enter.

Or press the Windows key, type firewall, and choose Windows Defender Firewall with Advanced Security.

Master keys needed: Windows may ask "Do you want to allow this app to make changes to your device?" Select Yes. This is the master-keys moment from Part 1.

What you'll see in the left column

  • Inbound Rules: visitors coming in (this is where we work)
  • Outbound Rules: traffic leaving your computer
  • Connection Security Rules: advanced settings we won't touch
  • Monitoring: what's active right now

Step 4: Read the Inbound Rules

Click Inbound Rules in the left column.

Don't panic. You'll see hundreds of rules. That's normal. Windows and your apps create them for everyday features. We won't change any existing rule (except the optional household key in Step 7, Path B).

What the columns mean

Scroll right to see Remote Address, Protocol, and Local Port.

Step 5: Install Your First Lock

We'll lock door 135 (RPC, a Windows networking service).

  1. In the right-hand Actions panel, click New Rule...
  2. Rule Type: choose Port → Next
  3. Protocol and Ports: choose TCP, then Specific local ports: 135 → Next
  4. Action: choose Block the connection → Next
  5. Profile: check Domain, Private and Public → Next check Domain and Public, uncheck Private → Next depends on your path (go back to Step 2 to choose) → Next
  6. Name: Lock - RPC 135
  7. Description (optional): Stops visitors from other devices reaching RPC door 135.
  8. Click Finish.
Your first lock is in. Visitors from other devices can no longer reach door 135 on any network.on Public or Domain networks.
Why every name starts with "Lock - ": it makes your locks easy to find, check, and remove later. Parts 4 and 5 rely on this name.

What each lock changes

  • 2179: other PCs can't open your Hyper-V virtual machines remotely. Opening them on this PC is unaffected. Part 3 covers guest rooms.
  • 5040: may affect cross-device features such as Nearby Sharing or Phone Link. If one stops working, switch this lock off (page 11).
  • 7680: Microsoft says blocking it turns off peer-to-peer sharing, while updates still download normally over HTTP/HTTPS.

Step 7: The Household Key

Path A: you can skip this page. Your locks cover every network, and nobody needs a household key.
This step is for Path B only. Go back to Step 2 if you haven't chosen a path.

On your Private home network, Windows' built-in File and Printer Sharing rules let visitors in. Give them a household key so only devices on your home network get through.

  1. In Inbound Rules, find File and Printer Sharing (SMB-In) where the Profile column shows Private.
  2. Double-click it and open the Scope tab.
  3. Under Remote IP address, choose These IP addresses → Add...
  4. Choose Predefined set of computers → Local subnet → OK → OK.
  5. Repeat for any other enabled File and Printer Sharing rules with the Private profile that show Any under Remote Address.
Check first: if Remote Address already says Local subnet, that rule already has a household key. Leave it as it is.

A Special Case: Firmware Doors

Doors 623, 664 and 16992–16995 belong to Intel Active Management Technology (AMT), a hardware management feature mostly found on business PCs.

Windows locks may not cover these doors. Intel's documentation says that when AMT is enabled, messages on a wired network go directly to Intel AMT, before Windows sees them. Over Wi-Fi, the Windows wireless driver passes them along.

What to do if you saw these doors in Part 1

  1. You can still add Windows locks named Lock - Intel AMT 16992 and so on, but don't rely on them alone.
  2. If you don't use AMT, the real fix is to switch it off in your PC's firmware (BIOS/UEFI) settings. Menu names differ between manufacturers, so follow your PC maker's support page.
  3. If this is a work computer, ask your IT department before changing anything. They may use AMT to manage it.

Step 8: Undoing a Mistake

If something you need stops working after a lock goes in (a printer, a shared folder, Nearby Sharing), undo that lock right away.

Switch a lock off (keeps it for later)

  1. Go to Inbound Rules.
  2. Find your lock. Clicking the Name column header sorts names so your Lock - rules sit together.
  3. Right-click it → Disable Rule. The door unlocks right away.

Remove a lock completely

  1. Right-click the lock → Delete → Yes.
One lock at a time: after each new lock, try the features you care about. If one breaks, you'll know which lock caused it.

Step 9: Testing Your Work

Check that your locks exist

Open a standard Terminal (the visitor pass from Part 1) and run:

Get-NetFirewallRule -DisplayName "Lock - *" |
  Format-Table DisplayName, Enabled, Action, Profile -AutoSize

Each lock should show Enabled: True and Action: Block. If Windows says access is denied, close the window and use Terminal (Admin) for this check.

Optional: test from another Windows PC

  1. On this PC, run ipconfig and note the IPv4 Address (for example, 192.168.1.25).
  2. On another Windows PC on the same network, open Terminal and run:
Test-NetConnection -ComputerName 192.168.1.25 -Port 135

Replace the address with yours. TcpTestSucceeded : False means the door stayed shut. The test may pause for a while first, because Windows Firewall drops blocked visitors without replying.

Path B note: if your network is set to Private, a test of door 445 from a home device can succeed. That's expected, because devices on your home network have a household key.

Finish by typing exit to close the gate.
